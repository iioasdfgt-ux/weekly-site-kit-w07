# 한글 검수 시스템

> **글을 다 쓴 뒤에 이 파일을 연다.** 글을 쓰는 중에는 열지 않는다 — 검사관을 만드는 손 위에 앉히면 글이 몸을 사린다.
> 이 스킬이 검수·윤문의 **단일 정본**이다. 에이전트 파일(`hangul-reviewer`·`hangul-polisher`)은 이 스킬을 여는 손일 뿐이다.

## 0. 기준선 — 누가 썼든 같은 판정표

**이 기준은 외부에 발행되는 상업 문서와 같다.** 학생 작업이라고, 첫 작업이라고, 마감이 급하다고 기준을 낮추지 않는다. 판정표에 "학생이니까"라는 예외 칸은 없다.

동시에 **기준을 맞추려고 쓴 사람의 문체를 다른 사람의 문체로 바꾸지 않는다.** 검수가 지키는 것은 정확성과 호흡이고, 개성은 지켜야 할 대상이다. 좋은 검수를 거친 글은 더 안전해지는 데서 그치지 않고 **원래 쓴 사람의 말투 그대로 더 잘 읽혀야 한다.**

## 1. 세 모드 — 한 대화에서 둘을 하지 않는다

| 모드 | 하는 일 | 누가 | 읽을 파일 |
|---|---|---|---|
| **검수** | 문제를 **표시만** 한다. 문장을 다시 쓰지 않는다 | `hangul-reviewer` (빈 컨텍스트) | `00` → `10` → `20` → `30` → `40` |
| **윤문** | 검수표에서 승인된 지적만 반영한다 | `hangul-polisher` | `00` → `50` + 검수표 |
| **윤문 반영 점검** | 원문과 윤문본을 나란히 놓고 윤문이 만든 손상을 잡는다 | `hangul-reviewer` (새 빈 컨텍스트) | `00` → `50` §4 → `40` |

**만든 손이 자기 결과를 판정하지 않는다.** 같은 대화에서 쓰고 점검하면 쓸 때 쓴 가정이 점검에도 그대로 실린다. 쪼갠 문장을 리듬으로, 억지로 이은 문장을 매끄러운 문장으로 본다.

## 2. 순서 (타이트 루프)

```
글 완성
 → ① 기계 검사   python3 .claude/skills/hangul-review/scripts/kcheck.py <파일|폴더>
 → ② 검수        hangul-reviewer  (빈 컨텍스트, 표시 전용)
 → ③ 승인        쓴 사람이 지적마다 반영/보류를 고른다
 → ④ 윤문        hangul-polisher  (승인된 지적만 + 원본 백업)
 → ⑤ 반영 점검    kcheck.py --compare <원본> <윤문본>  →  hangul-reviewer 윤문 반영 점검 모드
 → 🔴 0건이면 끝. 남으면 ④로 — 최대 2회. 그래도 남으면 그 구간은 원문 유지하고 쓴 사람에게 넘긴다
```

`/hangul-check <파일>` 명령이 이 순서를 한 번에 돈다.

## 4. 계측은 볼 자리이지 점수가 아니다

`kcheck.py`가 찍은 자리는 **사람이 판정할 후보**다. 개수를 0으로 맞추려고 문장을 합치거나 자르지 않는다. 기계가 통과시켰다고 끝난 것도 아니다 — 주어 누락·비유의 적절성·억지 연결은 기계가 못 본다.

## 5. 경계

- **사실을 만들지 않는다.** 원문에 없는 수치·수상·클라이언트·협업·후기를 검수 제안이나 윤문으로 끼워 넣지 않는다.
- **검수자는 수정하지 않는다.** 위치·문제·근거·수정 방향 한 줄까지만.
- **원본을 덮어쓰지 않는다.** 윤문 전 원본을 `_review/` 아래에 백업한다(`50_윤문규율.md` §3).
- **배포는 쓴 사람이 한다.** 이 스킬은 배포·커밋·업로드를 하지 않는다.
