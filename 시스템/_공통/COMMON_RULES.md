# 학생 AI 공통 조립·커스텀 규칙 (5~7주 모든 시스템) v3.0

각 시스템 DESIGN.md는 이 파일을 먼저 따르고, 시스템 고유 규칙만 덧붙인다. 두 문서가 부딪히면 이 파일이 이긴다.
이름 규칙·공통 커스텀 항목·선택 기록 형식은 `NAMING_AND_CUSTOM.md`가 정본이다.
(v1: 학생 D·E·F 시험에서 문서마다 같은 질문에 다른 답을 내 헤맨 것을 모음 · v2: 공통 커스텀 항목 6개와 선택 기록 추가 · v2.1: 학생 G 시험 — 글자색·은은하게·명암 정체성·고정 라벨·표시 변환·링크·og:image · **v3.0 (2026-10-04 교수 지시): 커스텀 제약 해제** — 학생이 요소를 지우거나 넣거나 바꿔 달라고 하면 들어준다. 정체성 충돌·교수 가이드를 이유로 거절하지 않는다)

## 0. 커스텀에 제약이 없다 (v3.0 — 이 절이 아래 모든 절보다 먼저다)
- 학생이 요소를 **지워 달라 · 넣어 달라 · 옮겨 달라 · 바꿔 달라**고 하면 그대로 해 준다. 섹션·모듈·사진 칸·버튼·움직임·격자·글자 크기·색 — 무엇이든 대상이다.
- 거절하지 않는다. "교수 가이드상 안 됩니다", "이 시스템의 정체성이라 바꿀 수 없습니다", "커스텀은 한 가지만", "my-style.css 밖은 고칠 수 없습니다" 같은 말을 하지 않는다. 다른 시스템으로 갈아타라고 권하지도 않는다.
- 학생 사이트 복사본(`weeks/NN/site/`)의 `index.html`·`style.css`·`tokens.css`·`sig.js`·`my-style.css` 모두 고칠 수 있다. `시스템/NN주/` 원본 폴더는 **되돌리기용 원본**으로 그대로 두고, 고치는 일은 복사본에서 한다(원본을 고쳐야만 되는 요청은 없다).
- 바꾼 뒤 화면이 깨지면(가로 넘침·글자 잘림·사진 안 뜸) 그 자리를 고쳐 맞춘다. 요청 자체를 되돌리지 않는다.
- 바꾸면 시스템의 인상이 크게 달라지는 요청(예: 한 번에 하나만 열리는 목록을 전부 펼치기)은 **적용한 뒤** "○○가 이렇게 바뀌었습니다" 한 줄만 알린다. 묻고 멈추지 않는다.
- 학생 문장을 지키는 규칙(§2 첫 줄 — 한 글자도 바꾸지 않는다, 지어내지 않는다)은 제약이 아니라 학생 보호라 그대로 둔다.

## 1. 학생이 고치는 곳
- **빠른 커스텀**은 `my-style.css`. 공통 항목 6줄(`--my-bg` `--my-point` `--my-type` `--my-motion` `--my-density` `--my-image`) + 시스템 고유 항목 최대 2줄. `sig.js`가 읽어 클래스를 붙인다. 이 줄로 되는 요청은 이 줄로 먼저 한다(되돌리기 쉽다).
- **그 밖의 요청**(요소 삭제·추가·위치·크기·구역 순서·동작)은 복사본의 HTML·CSS·JS를 직접 고쳐 들어준다(§0). 새 색이 필요하면 `my-style.css`에 변수를 한 줄 더 만들어 쓴다.
- **콘텐츠**는 세 곳: `index.html`(문구) · `assets/`(사진) · `assets/CREDITS.tsv`(출처 한 줄).
- 시작은 `golden.html`을 `index.html`로 복사한 뒤 슬롯부터 바꾼다. 구역을 더하거나 빼는 일은 그다음에 학생이 말하는 대로 한다.

## 2. 문구
- 학생 문장은 한 글자도 바꾸거나 줄이지 않는다. 슬롯 상한을 넘으면 화면은 그대로 두고 `상한 초과: 슬롯(글자 수/상한)`을 한 줄 보고.
- 학생이 주지 않은 문구는 쓰지 않는다. 6주부터(취향 아카이브)는 `<title>`·meta description·첫 화면 사진·사진 alt를 그 주 주제카드의 '공통 — 제목·설명·사진 이름' 표대로 정하고, 그 표가 아래 5주 규칙보다 먼저다. 예외는 기계 규칙뿐: `<title>` = `이름 — 주제명`(5주 "내가 좋아하는 한 사람", 6주 "머물고 싶은 공간 세 곳", 7주 "매일 고르는 물건 다섯 개"), meta description = 내 한 문장, 사진 alt = `이유 N 근거 사진`. 출처 줄의 사진 설명은 학생이 준 경우에만.
- **긴 이름은 시스템이 책임진다(코드)**: 이름·제호 크기는 공백을 포함한 실제 렌더 폭을 폰트 로드 후 재서 맞춘다. 한글 12자·영문 24자까지 390에서도 잘리거나 어절 중간에서 끊기지 않고, 이름이 그 화면에서 가장 큰 글자로 남아야 한다(같은 크기의 문장 안에서 이름이 주어로 맨 앞에 서는 시스템은 동률 허용 — 그 시스템 DESIGN.md에 명시).
- 예시 인물 표기(`.note`)는 골든·예시 페이지 전용 — 학생 페이지에서는 태그째 지운다.
- 슬롯 밖 **고정 라벨**("이유", "근거", "출처:", "내 작업에 가져올 한 가지" 등)은 시스템 문구다 — 그대로 둔다.
- **표시 변환**(CSS 대소문자·자간·세로쓰기)은 원문을 바꾸지 않으므로 허용. 단 시스템 DESIGN.md에 어느 자리에서 변환되는지 적어 둔다.
- 링크 주소를 학생이 주지 않았으면 `href="#"`로 두고 `링크 주소 없음: 라벨` 보고.
- `og:image` = 첫 사진의 상대경로(사진이 없으면 태그째 지움). 7주 배포 때 절대주소로 바꾼다.
- 빈 슬롯은 태그째 지운다(배치는 CSS가 알아서 바뀐다). 해석이 비면 채우지 않고 `해석 칸이 비었습니다: 이유 N` 보고. 영문 이름이 없으면 영문 태그를 지우고, 영문 이름을 쓰던 장식 자리는 한글 이름.

## 3. 사진
- 새 사진: `assets/`로 복사 → 파일명 영문 소문자·숫자·밑줄 → `CREDITS.tsv`에 한 줄 → `width`·`height`는 실제 픽셀.
- 세로가 가로보다 길면 세로형, 아니면(정사각 포함) 가로형.
- 파일을 못 찾으면 figure를 지우고 `사진 없음: 파일명` 보고.
- 사진이 0장이어도 모든 시스템은 성립해야 한다(시스템의 책임).

## 4. 학생 말투 → 공통 항목

모든 시스템 DESIGN.md는 커스텀 항목 표 위에 **명암: 자유** 한 줄을 둔다(v3.0부터 '고정' 값은 쓰지 않는다 — 학생이 바탕을 짙게·밝게 바꾸면 그대로 바꾼다).

| 학생 말 | 번역 |
|---|---|
| "○○ 바탕", "배경은 ○○" | `--my-bg`. 짙은지 밝은지로 뒤집지 않는다 |
| "○○ 포인트", "강조는 ○○" | `--my-point` |
| "○○이랑 ○○" (역할 말 없음) | 명도 차가 크면 짙은 쪽 = 바탕, 비슷하면 첫째 색 = 바탕 |
| "○○ 바탕에 ○○색으로" (둘째 색 역할 없음) | 둘째 색 = `--my-point` |
| "글자(글씨)는 ○○색" | `--my-point`. 시스템이 포인트를 글자에 쓰지 않으면 적용하고 `글자색 요청: 이 시스템은 글자색을 바탕에 맞춰 자동으로 정합니다 — ○○은 포인트 자리에 썼습니다` 보고 |
| 바탕 명도가 시스템 기본과 반대 (예: 밝은 종이가 기본인데 짙은 바탕) | 그대로 적용한다. 글자·선 색은 바탕에 맞춰 뒤집는다 |
| "흑백", "무채색", "색 없이" | `--my-bg: #111111` 또는 `#FAFAF7`(시스템 기본 명도 쪽) · `--my-point: none` · `--my-image: mono` |
| 시스템 기본 모양과 다른 요청 (구역 묶기·목록 전부 펼치기·격자 바꾸기 등) | 그대로 적용한다(§0). 변수로 안 되면 복사본 HTML·CSS·JS를 고친다. 적용 뒤 바뀐 모습 한 줄 |
| 글자 대비 4.5:1 미만 | 적용하되 글자 파생색만 보정, 면 색은 그대로. 보정으로도 안 되면 보고 |
| 명조·신문·책·클래식 | `--my-type: serif` |
| 고딕·깔끔·모던·포스터·강한 | `--my-type: sans` |
| 타자기·코드·자막·기록 | `--my-type: mono` (없으면 sans + 보고) |
| 손글씨·동글동글·귀여운·따뜻한 글씨 | `--my-type: hand` (없으면 가장 가까운 것 + 보고) |
| 제일 조용하게·차분하게·움직임 없이 | `--my-motion: 0` |
| 기본·그냥 · **은은하게·잔잔하게·부드럽게** | `--my-motion: 1` (움직임을 끄라는 뜻이 아니다) |
| 신나게·크게 움직이게·요란하게 | `--my-motion: 2` |
| 더 비게·여유 있게·미니멀 | `--my-density: 0` |
| 꽉 차게·빽빽하게·글자 크게·사진 크게 | `--my-density: 2` (사진·글자 크게는 밀도 2로 적용하고 보고) |
| 사진 흑백으로 | `--my-image: mono` |
| 사진에 색 입혀·톤 맞춰 | `--my-image: tint` |
| 이 사이트처럼 사진 처리 | `--my-image: native` |
| 표에 없는 요청 | 가까운 줄이 있으면 그 줄로, 없으면 복사본 HTML·CSS·JS를 직접 고쳐 적용하고 `표에 없음: "요청" → ○○로 적용` 보고 |

- 색 이름 → hex 공통표: 크림 `#F3E9D2` · 분홍 `#F4A3B8` · 핫핑크 `#FF4F8B` · 주황 `#F28C38` · 빨강 `#D7263D` · 노랑 `#F5C518` · 연두 `#9BD770` · 청록(짙은) `#0E4F52` · 하늘 `#8EC9E8` · 파랑 `#1F4FD6` · 남색 `#1B2A4A` · 보라 `#6B4FA3` · 갈색 `#6B4A2F` · 회색 `#9A9A9A` · 검정 `#111111` · 흰색 `#FAFAF7`.

## 5. 보고
AI는 조립·커스텀이 끝나면 보고 줄(상한 초과·해석 빈칸·사진 없음·표에 없음·대비 부족·바뀐 모습)을 모아 학생에게 한 번에 보여 준다. 보고 줄은 알림이지 거절이 아니다.

## 6. 선택 기록
회고(`끝`) 때 AI는 `weeks/NN/choices.md`를 `NAMING_AND_CUSTOM.md` §3 형식으로 채운다. "바꾼 요소"는 STEP 05 커스텀에서 바꾼 것을 **모두** 적는다(여러 개면 줄을 나눈다. 처음 설정한 커스텀 항목 값들은 위 칸들에 이미 기록된다). 값은 `my-style.css`에서 그대로 읽고, 고유 항목은 DESIGN.md의 번역 줄로 공통 칸에 옮긴다. "고른 이유"와 "기준 한 줄"은 학생 말 그대로.
